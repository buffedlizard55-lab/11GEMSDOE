# Candidate geological hypotheses — preregistration, not results

**Status as of 2026-09-27:** five distinct candidates drafted. `H1` was implemented and screened on the team's checksum-pinned data bridge using four spatially blocked folds, paired against the same detector with the same base/topographic/radiometric features. The held-out-label-only DTI was 0.149795 for H1 versus 0.149986 for control at the fixed 0.20 emission threshold; H1 **did not beat the holdout best and is not approved for submission**. See the [machine-readable experiment record](evidence/h1_holdout_2026-09-27.json). The remaining ranking is provisional and is not a claim of measured lift.

## What the contest data actually documents

The official problem page describes feature layers including conductivity/depth, detrended elevation and its slope, dilatation rate, shear strain rate and second invariant of strain, isostatic gravity anomaly and its slope, magnetic anomaly/intensity and derivatives/source-depth estimate, and earthquake density. It states the input feature raster is UTM 11N / EPSG:32611 at 100 m. The about page confirms GeoDAWN collected airborne magnetic and radiometric data with lidar over the region. Feature band names must be read from the actual TIFF before coding; do not infer exact band indices from prose.

## Viability and data access

The official competition data tab redirected to login during this review, but the public `buffedlizard55-lab/5GEMSDOE` repository contains a checksum-pinned bridge of the competition-page Dropbox mirror files. This session assembled the feature, label, and sample-submission rasters into excluded `.cache/` storage and independently matched their SHA-256 digests to that bridge's manifest. This is sufficient to run the reported local proxy experiment, but it is **not a direct independent download from DrivenData**; the source chain and limitation are documented in [Sources](SOURCES.html) and the [H1 experiment record](evidence/h1_holdout_2026-09-27.json).

H1 is not viable for a contest slot on this evidence: it slightly underperformed its paired control on the current four-fold holdout. H2 is the next candidate to consider, not an approved submission. No additional external scientific dataset is required for initial H2 evaluation because its core channels are in the provided competition features. If a later H5 variant requires high-resolution DEM coverage, use the official `1m_DEM_links.csv` supplied by the contest and check actual USGS 3DEP coverage and licensing; the CSV's contents/complete tile coverage have not been independently inspected in this checkout.

## H1 validation protocol (must precede any use of a submission slot)

1. Inventory the actual official feature bands by description, units, nodata, CRS, affine transform, and valid mask; identify the label raster's semantics and verify the official sample submission grid.
2. Establish a fixed spatial-block split with non-adjacent train/validation blocks. Buffer fold boundaries by at least the metric's 300 m support (three 100 m pixels) to limit neighborhood leakage. Publish block IDs/seed and use the same folds for every comparison.
3. Train/evaluate the current baseline and H1 on exactly the same folds and data budget. Use no held-out labels for thresholding, channel scaling, or hyperparameter selection. Any tuning requires inner spatial folds.
4. Score with the official distance-weighted Tversky definition (alpha=0.2, beta=0.8, triangular support=300 m), confirm implementation against a trusted organizer example/reference, and report each fold, mean, dispersion, and bootstrap/block uncertainty. Measure false-positive/false-negative components and candidate pixel budget as diagnostics.
5. Define “beats current holdout best” before running: paired improvement in mean DTI, no unacceptable fold collapse, and evidence of improvement beyond noise/selection effects. Record negative or inconclusive outcomes too.
6. State the limitation: known-label spatial holdout measures generalization to held-out mapped faults, not truth on unmapped faults. It is a proxy, and public leaderboard feedback is not a substitute for the private expert labels.
7. Only if H1 passes, package a uniquely named candidate with its model/config/data hashes and distinct short note. Otherwise do not submit it; proceed to H2 using the same locked protocol.
